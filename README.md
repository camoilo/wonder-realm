# 多模式对话机器人

一个完全在本机运行的对话应用：模型走本地 Ollama，数据存本地 SQLite，不依赖任何云端 API。支持三种对话模式，带角色设定、可随时调整的生成要求、跨会话的长期记忆，以及完整的消息编辑与重生成能力。

## 三种模式

| 模式 | 生成内容 | 绑定角色 | 长期记忆归属 |
|---|---|---|---|
| **角色对话** | 只有角色说出的话 | 是，会话创建时选定 | 按角色，该角色所有会话共享 |
| **角色情境** | 角色话语 + 情境说明 | 是，与角色对话共用同一套角色 | 与角色对话共用同一份角色记忆 |
| **自由情境** | 自由生成的对话与情境 | 否 | 按会话独立保存 |

角色对话与角色情境共享角色设定和长期记忆——在任一模式下聊过的关键信息，切到另一个模式也记得。角色之间、会话之间的记忆互不可见。

但两个角色模式的**会话列表相互隔离**：角色对话里只列出角色对话创建的会话，角色情境里只列出角色情境创建的会话，互相看不到、也打不开；切换模式 Tab 会回到你上次在该模式看的那条会话。三种模式里，只有自由情境的会话与角色无关。

## 主要功能

**角色设定**：头像（可选）、外观、性格、语言风格、背景故事，随时可改，下一次生成即生效。选头像时的流程是：**先校验**（格式、大小上限 10MB、图片最短边至少 256px），**再拖动裁剪成正方形**（可缩放 1×～3×），保存时缩成 256×256 存进数据库——所以头像跟着数据库一起备份、一起恢复。

**让模型生成角色**：新建角色时可以让模型直接写好整个角色设定（只写文字，不管头像和背景），填一句话描述想要的设定即可，留空则由它自由发挥，不满意可以点"换一个"重来。生成有两种模式：

- **开放模式**：生成的姓名、外观、性格、语言风格、背景故事全部直接展示，可以随便改。
- **探索模式**：只公开**姓名与外观**，另外三项**上锁**——它们照常参与生成（角色的性格是真的存在、会体现在对话里），但界面上不显示，接口也不下发，你得在对话中慢慢了解这个角色。想直接看也可以：点"公开角色设定"，确认后**永久解锁**并开放修改（解锁是单向的，不能反悔再锁上）。

生成用的是**当前选中的模型**，并且**跟着顶栏的思考开关走**——开着思考会明显更慢（实测同一提示词常见 60 秒左右，偶发超过 5 分钟），嫌久可以先关掉思考模式再生成。等待上限默认 600 秒，可在 `config.yaml` 的 `character_gen.timeout` 调整；真超时会明确告诉你是超时，而不是一句没头没尾的失败。

**对话背景**：每个角色最多可放 **5 张**图，在角色对话 / 角色情境模式下作为对话区背景（**整图居中**，比例不合时两侧或上下留白，既不裁切也不拉伸）；对话区底部中央有 `‹ 2 / 5 ›` 可随时切换。自由情境模式、未选会话、角色已删除时都保持空白背景。背景图存在数据库里，同样跟着备份走。

**生成要求**：挂在会话上而不是角色上，因此同一个角色可以有"简短闲聊"和"详细演绎"两种用法互不干扰。每个模式一套字段，其中**发散程度**是四个标签（严谨 / 稳定 / 标准 / 放飞），调的是模型每次回答的随机程度——**它不是给模型的文字要求，不写进提示词**，界面上也不显示数值。角色情境模式另有**导演指令**，单独成段注入提示词——它只影响情境与剧情走向，不会作为消息进入对话历史，角色也不会"说出"收到了指令。自由情境模式另有**情境/台词配比**（只有情境 / 情境为主 / 均衡 / 台词为主）：可以整段只写情境、完全不出现台词，也可以让情境远多于台词，不必两者交替出现。

**长期记忆**：会话内消息超过阈值（默认 20000 字符）后，后台自动把较早的消息压缩成一份结构化摘要，不需要用户操作。摘要会注入后续生成的提示词，可在右侧面板查看与手动修改。摘要长度、压缩阈值、批量条数都可配置。

**会话内搜索**：顶栏右侧有搜索框，输入关键词即时把所有命中处**标黄**（当前那一处用更深的橙色），↑/↓ 在命中之间环形跳转并把它滚到视野中间（Enter 下一个、Shift+Enter 上一个、Esc 清空）。框的宽窄不随输入变化。搜索覆盖当前显示出来的消息（含情境说明），只搜显示中的——归档折叠着的不参与。关键词按字面匹配、大小写不敏感。

**我的设定（你是谁）**：右侧面板里可以设定**你本人**——头像（可选）、名字、身份、外观。填好之后可以**存为预设**（含头像），下拉列表里选一条就能把那份设定载入表单；删除预设不影响正在使用的那份。**身份与外观会写进角色两模式的提示词**，让角色知道正在跟谁说话；头像与名字会显示在你自己的消息旁（气泡右侧，与角色消息镜像）。三项都可以留空。自由情境模式不使用这些内容：那里你是写故事的人，不是故事里的角色，所以那个模式下连这个标签都不出现。

**世界设定**：右侧面板里可以给故事定一个**世界**——**世界名称**（只给自己辨认，**不发给模型**）、**描述**（详细信息）、**规则**（独属于这个世界的规则）与**词库**（专有名词及其解释，一条一行，可增删）。四项都可以留空，也可以随时改，下一次生成即生效。**全局一份**，三种模式都用得上（自由情境的故事同样发生在某个世界里）。除了名称，描述 / 规则 / 词库都会写进提示词，位置在**角色设定之前**——世界是最外层的框架：模型会遵守这些设定、按给定含义使用词库里的名词，但不会把这份设定原文念出来。

**每处输入都有字数上限**：消息与情境 2000 字、角色姓名 20 字、外观 / 性格 / 语言风格 600 字、背景故事 1200 字、题材文风 60 字、附加要求与导演指令 500 字、记忆 2000 字、会话标题 40 字、生成提示词 200 字、我的设定里的名字 20 字 / 身份 300 字 / 外观 600 字、世界名称 40 字 / 描述 2000 字 / 规则 2000 字、词库每条的名词 30 字 / 解释 150 字且最多 30 条。输入框**右下角实时显示"已用 / 上限"**，到九成时转橙色提醒；到上限就打不进更多字（粘贴超长也会被截），直接调接口同样会被拒（422）。上限只写在后端一处（`app/limits.py`），前端从 `/api/limits` 取同一份数字，不会出现"打得进、存不下"。

**消息操作**：任意消息都可编辑（双击气泡或点"编辑"，弹窗居中显示）与删除（单条或连着后面一起删）；生成消息可重新生成，以该消息之前的上下文为基准替换。**用户消息也能重新生成**——保留这条消息、只重做它之后的回复，所以中途"停止"导致这轮没有回复时可以直接重来。生成过程中可以随时**停止**，已经流出的部分照常保留，不会白费。会话绑定的角色被删除后，该会话只可查看，重新生成按钮不再提供（即使通过接口发起也会被拒绝，且不会删掉已有消息）。

**继续生成**：自由情境模式下，发送键上方有一个"继续"键，点一下等于自动替你发一条"继续"，让模型接着上一条回复往下写——想让它多写一段又懒得打字时很方便。它不会动你输入框里正在写的草稿。

**会话标题自动命名**：创建会话时留空标题，说够内容后由模型异步总结一个标题；手动改过名的会话不会再被自动覆盖。

**模型随时切换**：顶栏下拉框只列本机已安装的模型，切换立即生效、重启不丢。**首次使用不预选模型**——先在顶栏选一个；之后每次启动都沿用你上次的选择。没选模型时顶栏会提示，真去生成也会明确告诉你要先选模型，而不是抛一句看不懂的报错。思考型模型（qwen3 等）与普通模型都能直接换——推理过程由应用层剥离，只显示"思考中"占位，不会污染消息内容。

**思考模式开关**：模型下拉框旁边有一个开关，可以**关掉思考模式**。思考型模型在回答前会先推理一遍，关掉它能明显加快回复（实测同一个模型从 8.4 秒降到 1.4 秒）；普通模型没有思考模式，这个开关会置灰、点了也不起作用。选择会记住，重启仍生效。

## 技术栈

| 层 | 选型 |
|---|---|
| 模型服务 | 本机 Ollama（默认 `http://localhost:11434`） |
| 后端 | Python 3.13 + FastAPI + SQLite（WAL 模式） |
| 依赖管理 | uv |
| 前端 | Vue 3（CDN 引入，无构建流程）+ 原生 CSS |
| 流式输出 | SSE（`fetch` + `ReadableStream` 手动解析） |

设计取舍与实现细节见 [DEVELOPMENT.md](./DEVELOPMENT.md)。

## 开始使用

### 1. 准备 Ollama

安装 [Ollama](https://ollama.com/download) 并拉取一个模型：

```powershell
ollama pull qwen2.5:3b
```

确认服务在跑（Ollama 安装后会自动常驻）：

```powershell
curl http://localhost:11434/api/tags
```

小模型响应快、占用低，适合先跑通；想要更好的角色扮演与格式遵循效果，可以换更大的模型（例如 `qwen3.5:4b`），在界面顶栏切换即可。

**（可选）把 KV cache 量化打开，给长上下文省一半内存**：本项目把上下文窗口默认设成 32768 token，而 Ollama 的 KV cache 默认是 f16，在这个窗口下要占约 1 GB。设一个用户环境变量就能量化成 q8_0（质量基本无损）：

```powershell
[Environment]::SetEnvironmentVariable("OLLAMA_KV_CACHE_TYPE", "q8_0", "User")
```

然后**从托盘退出 Ollama，再从开始菜单重新启动**（这个变量由托盘应用传给服务进程，不重启不生效）。实测 `qwen3.5:4b` 在 32768 窗口下总占用从 4085 MiB 降到 3606 MiB（KV cache 从 1024 MiB 降到 544 MiB）。它是 Ollama 服务端的**全局**设置，会影响这台机器上所有连 Ollama 的程序；不设也完全能跑，只是多用几百 MB 内存。

### 2. 安装 uv

```powershell
powershell -c "irm https://astral.sh/uv/install.ps1 | iex"
```

### 3. 安装依赖

在项目目录下执行（uv 会按 `.python-version` 自动准备 Python 3.13，无需手动装）：

```powershell
uv sync
```

### 4. 启动

```powershell
uv run run.py
```

看到 `Uvicorn running on http://127.0.0.1:17800` 后，浏览器打开：

```
http://127.0.0.1:17800
```

也可以直接双击项目根目录的 `start.bat`：省去开终端敲命令，启动后会自动用默认浏览器打开页面；服务已在运行时再双击一次不会重复启动，只会把页面重新打开。关掉那个命令行窗口即停止服务。

### 5. 第一次使用

1. 在**角色对话**或**角色情境**模式下点"新建角色"，填写角色设定；也可以让模型**自动生成**一个（见下）
2. 点"新建会话"（标题可留空，之后会自动命名），开始对话
3. 右侧面板里可以调生成要求、改角色设定、看记忆
4. 想写自由剧本就切到**自由情境**模式，直接新建会话即可

> 两个角色模式的会话是分开的：在角色对话里建的会话不会出现在角色情境的列表里，反之亦然。切模式 Tab 会回到你上次在该模式看的那条会话。

## 界面说明

三栏布局，左右两栏都可以收起，对话内容始终居中：

```
┌──────────┬──────────────────────────────────────┬──────────────┐
│模式Tab   │ [☰] 标题 [模式] [模型] [思考] [面板] │              │
│          ├──────────────────────────────────────┤  右侧面板    │
│列表区    │          消息流（居中留白）          │  · 生成要求  │
│·角色列表 │                                      │  · 角色设定  │
│·或会话   │                                      │  · 记忆查看  │
│──────────├──────────────────────────────────────┤              │
│[新建]    │      [输入框        ] [发送][↓]      │              │
└──────────┴──────────────────────────────────────┴──────────────┘
```

- 每条消息的**气泡上方那一行显示名字与发送时间**（精确到秒，如 `12:34:45`）：角色两模式下是"角色名 + 时间"（你自己的消息显示你在"我的设定"里填的名字，靠右）；自由情境模式没有名字，那一行就只有时间。鼠标悬停在时间上可以看到完整日期时间
- 消息悬停后出现操作条：复制 / 编辑 / 删除 / 重新生成；也可以直接双击气泡进入编辑
- 两种角色模式下，助手消息左侧是**方形头像**（没上传图片就显示姓名首字），**角色名显示在气泡正上方**（微信式）；头像位置固定，换图不影响气泡排版
- 头像在**角色编辑弹窗**和**右侧面板的角色设定**里都能换，也可以一键移除；方形头像同样用在左侧角色列表里
- 选头像后会弹出**裁剪框**（带蓝色边线，白底图片也看得清裁到哪里）：拖动图片调整位置、用滑杆缩放（1×～3×），方框内的部分即头像；点框外或按 Esc 取消。图片不合适（不是图片、超过 10MB、最短边不足 256px、分辨率过高）会在选图处**直接提示原因**，不会静默失败
- 角色有背景图时，对话区显示**背景图**（整图居中、留白），底部中央出现 `‹ 2 / 5 ›` 切换键；**旁边还有一个「关闭背景」键**，点一下暂时不显示背景（按钮变成「显示背景」，切会话或刷新后恢复显示）。只有一张图时翻页键置灰，但关闭键照旧可用
- 头像与对话背景在**角色编辑弹窗**和**右侧面板的角色设定**里都能管理（面板里背景区就在头像下方）：背景最多 5 张、可一次选多张、可逐张删除
- 背景的**顺序可以调**：直接拖动缩略图，或用缩略图底部的 `‹`/`›` 逐格前移后移。**第一张是打开会话时默认显示的那张**，顺序也决定对话里"上一张/下一张"的先后
- 右侧面板是**标签页**：生成要求 / 世界设定 / 角色设定 / 我的设定 / 记忆（自由情境模式只有生成要求、世界设定与记忆）。每个标签**都有边框**（选中的那个用蓝色边框 + 白底标出），标签区与下面内容之间有一条明显的分隔线——左侧栏（"模式选择"下方、模式按钮下方）用的是同一款线。**标签栏固定在面板顶部、保存键固定在面板底部**（统一写「保存当前配置」），内容再长也不会被滚轮带走，也不会被内容量挤走；哪个标签有没保存的改动，它的右上角会出现一个小圆点，底部同时出现「未保存 / 还原」那一行（还原键还是"点两次确认"）。五个标签在 330px 面板里排成两行（3+2），不会把"生成要求"截成"生成要…"
- **"配置"开关常驻在顶栏最右**：没有打开会话时也在原位，只是变灰点不动。**面板展开后这个键就搬到面板顶部当标题**（显示为"配置 ‹"），点它收起面板；收起后它回到顶栏（"配置 ›"）。同一个开关始终只有一个去处，不会出现两个入口状态打架
- **删除角色只在左侧边栏**：点角色旁的 ✎ 打开编辑弹窗，里面的「删除角色」是唯一入口；右侧面板不再放删除键，避免在改设定的地方误删角色
- **用户消息与生成消息都能重新生成**：用户消息重新生成会保留这条消息本身、只重做它之后的回复；主动"停止"导致没有回复时，这是唯一的补救入口
- 点"编辑"或双击气泡会弹出**居中的编辑框**，长消息也不会把气泡拉变形；点框外或按 Esc 取消
- 新建/编辑角色的弹窗与编辑消息的弹窗**同宽（780px）**，五个设定框都有足够高度——角色设定是要写几段话的，不该在一个两三行的小框里来回滚
- 这两个弹窗底部的**取消 / 保存钉在弹窗底部**（连同"删除角色"和保存失败的提示）：内容再长、滚到哪一段，它们都在原处不动，不用先滚到底才能按
- 删除按钮下方的小菜单，点其他任意位置即自动收起（按 Esc 同样关闭）
- 会话绑定的角色被删除后，该会话只可查看，"重新生成"按钮不再出现
- 右侧面板里改过但还没保存时，该标签的右上角会出现一个小圆点，底部出现"未保存"和一个**还原**键：连着点两次即回到上次保存的内容（第一次点只是确认，5 秒内不点第二次会自动取消），不用弹窗确认；面板收起时改由顶栏"配置"键上的小圆点提示
- 生成中输入框右侧的按钮变为"停止"
- 发送键右侧还有个 **↓ 键**：往上翻看历史之后，点它直接平滑滚回最新一条，不用一路拖滚动条
- **自由情境**下发送键上方还有一个"继续"键（还没有可续的回复、或正在生成时置灰），点它等于自动发一条"继续"
- 右侧面板里带"✕"的栏位，那个 ✕ 不参与 Tab 键顺序，但照旧可以鼠标点击清空
- 每个输入框右下角都有 `已用/上限` 的实时计数（单行框里垂直居中、多行框里贴右下角），到九成变橙色
- **探索模式生成的角色**：右侧面板和"编辑角色"弹窗里，性格 / 语言风格 / 背景故事显示为一块 `🔒 已锁定` 说明，点其中的"公开角色设定"并确认后永久解锁；锁定期这两个入口只显示姓名与外观
- 左侧栏顶部有 **模式选择** 标题（居中加粗，下方一条分隔线）和三个模式按钮（角色对话 / 角色情境 / 自由情境），点一下切换模式
- 顶栏**模型下拉框左边**是**会话内搜索框**：输入即标黄，↑/↓ 或 Enter/Shift+Enter 在命中之间跳，**Esc 清空**；计数与两个跳转键一直都在（不随输入出现消失，所以框的宽窄始终不变）
- 左侧 `☰` 收起左栏，顶栏"配置"键收起右栏（面板展开时它在面板顶部，收起后回到顶栏），收起后对话区自动重新居中
- 被压缩归档的消息默认折叠为"已归档 N 条"，点击可展开查看原文
- 切换模式 Tab 只换左侧列表与当前会话：两个角色模式的会话互不显示，各自记住上次打开的那条

## 配置

改 `config.yaml` 后重启生效：

```yaml
ollama:
  base_url: http://localhost:11434
  model: ""                     # 首次使用不预选模型（留空），由用户在顶栏选；
                                 # 之后每次启动沿用上次的选择（存在库里的 app_settings）
  options:
    temperature: 0.9               # 兜底值：对话实际用会话的“发散程度”档位（标准档 = 0.9），
                                   # 记忆压缩与自动命名各自压到 0.3，改这里不影响它们
    num_ctx: 32768                 # 上下文窗口（token）。Ollama 默认 4096，这里显式加大；
                                   # 超窗时 Ollama 会从最前面静默截断，要和下面的记忆阈值配套改

memory:
  model: ""                       # 压缩用模型，留空 = 同对话模型
  compress_threshold_chars: 20000 # 未归档消息超过该字符数触发压缩（中文约 1.33 字/token）
  archive_batch_size: 20          # 每次归档的消息条数
  max_memory_chars: 600           # 记忆摘要长度上限

character_gen:
  timeout: 600                    # 让模型生成角色的等待上限（秒）。思考型模型开着思考很慢
                                  # （实测常见 60 秒、偶发超过 300 秒），嫌久可先关掉思考模式

chat:
  history_max_messages: 60        # 注入历史的最大条数（从最早开始截断）

naming:
  model: ""                       # 会话自动命名用模型，留空 = 同对话模型
  max_chars: 12                   # 自动标题字数上限
  min_user_chars: 8               # 用户累计发言少于该字数时先不命名

server:
  host: 127.0.0.1
  port: 17800                       # 避开其他项目常用的 8000/8080

backup:
  dir: ./backups                    # 备份目录；相对路径按项目根目录解析，可改成别的盘或网盘
  days: 14                          # 保留最近多少个自然日的备份（每次启动都备，一天可能多份）
  on_startup: true                  # 每次启动应用时自动备份一份

data_dir: ./data                  # 数据库目录
```

想快速验证记忆功能，可以把 `compress_threshold_chars` 临时改小（如 500），聊几轮就能看到归档折叠与记忆内容。

## 数据与备份

所有数据都在 `data/chatbot.db` 这一个 SQLite 文件里（含角色、会话、消息、记忆、模型选择，以及自定义头像与对话背景图）。数据库是单用户设计，没有鉴权，服务只监听 `127.0.0.1`，不要对外暴露。

**应用会自动备份**：**每次启动都导出一份**完整快照到 `backups/`，文件名形如 `chatbot-20260101-123456.db`（同一秒内重复启动会在名字后加 `-2`、`-3` 以免互相覆盖）。每份都先校验完整性再保留，**保留最近 14 个自然日**（含今天），更早的自动清理——所以一天里启动几次就会有几份备份，这是正常的。

> ⚠️ **不要在应用运行时手工复制 `chatbot.db`。** 库跑在 WAL 模式下，最近的对话可能还在 `chatbot.db-wal` 里、尚未并回主文件；只拷 `.db` 会得到一个缺少最后几轮、甚至缺表结构的快照——平时看不出问题，真拿它恢复时才发现丢的正是最后那段。自动备份走的是 SQLite 的在线备份接口，不受此影响。

- **想手动再备一份**：把应用重启一次即可（每次启动都会备一份）。
- **想换个地方存**（另一块盘、或网盘同步目录）：改 `config.yaml` 里的 `backup.dir`，相对路径按项目根目录解析，也可以直接写绝对路径。

**恢复步骤**

1. 关掉应用（那个命令行窗口）
2. 从 `backups/` 里挑一份，复制成 `data/chatbot.db`，并删掉旁边的 `data/chatbot.db-wal` 与 `data/chatbot.db-shm`（如果存在）
3. 重新启动应用

**彻底重置**：删掉 `data/chatbot.db`，下次启动会自动重建空库。`backups/` 里的历史备份不受影响，所以即使误删也还能从备份捞回来。

## 常见问题

**顶栏提示"无法连接 Ollama"**
Ollama 没启动或端口不对。执行 `ollama list` 确认能正常返回，必要时手动启动 Ollama。

**顶栏提示"所选模型未安装"**
上一次选的模型被删了，或换机器后模型没同步。在顶栏下拉框里重新选一个已安装的模型即可。

**生成很慢或首字等很久**
取决于本机模型大小与硬件。换更小的模型（如 `qwen2.5:3b`）会明显变快；界面上会先显示"生成中"，思考型模型会先显示"思考中"，都属于正常等待。

**模型不按格式输出情境**
小模型偶发。程序对标记的识别是宽容的——`SCENERY`/`SCENE`、小写、全角括号都认，台词写在标记之前也算话语，所以偶尔的用词偏差不会把内容打乱。真的一个标记都认不出时，整段会当作话语显示，不丢内容。可以在生成要求里把情境篇幅调小、或用更大的模型改善遵循度。

**某条回复只有情境、没有台词**
模型有时只写了场景。程序会照原样保留（情境显示为情境块，不硬塞台词），这条消息的正文就是空的；要补台词，编辑它即可（只有情境时也允许保存）。

**自由情境总是又写情境又写台词**
在右侧面板把"情境/台词配比"调成"只有情境"或"情境为主"即可。这个字段默认是"均衡"，模型拿不到明确要求时容易两边都写一点。

**在角色对话里看不到我在角色情境建的会话**
这是有意的：两个角色模式的会话列表相互隔离。切到角色情境模式就能看到，两边各自记住上次打开的那条会话。角色设定与长期记忆仍然是共用的。

**删了角色，那个会话还能用吗**
只能查看历史：输入框会禁用，"重新生成"按钮也不再出现。即使直接调接口发起生成也会被拒绝，并且已有消息不会被删除。想继续用就重建一个角色、开新会话。

**记忆什么时候更新**
每次生成完成后后台检查，超过阈值才压缩，不阻塞对话。想立刻看到效果就把阈值改小；压缩结果可在右侧面板查看与手动修改。

**删了消息，记忆会跟着变吗**
不会。记忆是"曾经发生过的事"的沉淀，已归档的内容不随消息删改回滚。需要修正就手动编辑面板里的记忆。

**必须联网吗**
运行时不需要，模型和数据都在本地。只有首次加载页面会从 CDN 取 Vue，如果完全离线，把 `index.html` 里的 Vue script 换成本地文件即可。

**换了端口后打不开页面**
服务端口在 `config.yaml` 的 `server.port`，默认 **17800**（刻意避开其他项目常用的 8000/8080）。用旧书签访问 8000 会连不上，改成 `http://127.0.0.1:17800` 即可，`start.bat`不受影响。

**数据库误删了 / 想回到几天前的状态**
去 `backups/` 里挑一份时间合适的备份，按上面"数据与备份"里的恢复步骤换回去即可（每次启动都会自动备一份，保留最近 14 天）。
