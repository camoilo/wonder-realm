# 多模式对话机器人

一个完全在本机运行的对话应用：模型走本地 Ollama，数据存本地 SQLite，不依赖任何云端 API。支持三种对话模式，带角色卡、可随时调整的生成要求、跨会话的长期记忆，以及完整的消息编辑与重生成能力。

## 三种模式

| 模式 | 生成内容 | 绑定角色 | 长期记忆归属 |
|---|---|---|---|
| **角色对话** | 只有角色说出的话 | 是，会话创建时选定 | 按角色，该角色所有会话共享 |
| **角色情境** | 角色话语 + 情境说明 | 是，与角色对话共用同一套角色 | 与角色对话共用同一份角色记忆 |
| **自由情境** | 自由生成的对话与情境 | 否 | 按会话独立保存 |

角色对话与角色情境共享角色卡和长期记忆——在任一模式下聊过的关键信息，切到另一个模式也记得。角色之间、会话之间的记忆互不可见。

但两个角色模式的**会话列表相互隔离**：角色对话里只列出角色对话创建的会话，角色情境里只列出角色情境创建的会话，互相看不到、也打不开；切换模式 Tab 会回到你上次在该模式看的那条会话。三种模式里，只有自由情境的会话与角色无关。

## 主要功能

**角色卡**：头像（可选）、外观、性格、语言风格、背景故事，随时可改，下一次生成即生效。选头像时的流程是：**先校验**（格式、大小上限 10MB、图片最短边至少 256px），**再拖动裁剪成正方形**（可缩放 1×～3×），保存时缩成 256×256 存进数据库——所以头像跟着数据库一起备份、一起恢复。

**对话背景**：每个角色最多可放 **5 张**图，在角色对话 / 角色情境模式下作为对话区背景（**整图居中**，比例不合时两侧或上下留白，既不裁切也不拉伸）；对话区底部中央有 `‹ 2 / 5 ›` 可随时切换。自由情境模式、未选会话、角色已删除时都保持空白背景。背景图存在数据库里，同样跟着备份走。

**生成要求**：挂在会话上而不是角色上，因此同一个角色可以有"简短闲聊"和"详细演绎"两种用法互不干扰。每个模式一套字段，其中**导演指令**（仅角色情境模式）单独成段注入提示词——它只影响情境与剧情走向，不会作为消息进入对话历史，角色也不会"说出"收到了指令。自由情境模式另有**情境/台词配比**（只有情境 / 情境为主 / 均衡 / 台词为主）：可以整段只写情境、完全不出现台词，也可以让情境远多于台词，不必两者交替出现。

**长期记忆**：会话内消息超过阈值（默认 6000 字符）后，后台自动把较早的消息压缩成一份结构化摘要，不需要用户操作。摘要会注入后续生成的提示词，可在右侧面板查看与手动修改。摘要长度、压缩阈值、批量条数都可配置。

**消息操作**：任意消息都可编辑（双击气泡或点"编辑"，弹窗居中显示）与删除（单条或连着后面一起删）；生成消息可重新生成，以该消息之前的上下文为基准替换。**用户消息也能重新生成**——保留这条消息、只重做它之后的回复，所以中途"停止"导致这轮没有回复时可以直接重来。生成过程中可以随时**停止**，已经流出的部分照常保留，不会白费。会话绑定的角色被删除后，该会话只可查看，重新生成按钮不再提供（即使通过接口发起也会被拒绝，且不会删掉已有消息）。

**继续生成**：自由情境模式下，发送键上方有一个"继续"键，点一下等于自动替你发一条"继续"，让模型接着上一条回复往下写——想让它多写一段又懒得打字时很方便。它不会动你输入框里正在写的草稿。

**会话标题自动命名**：创建会话时留空标题，说够内容后由模型异步总结一个标题；手动改过名的会话不会再被自动覆盖。

**模型随时切换**：顶栏下拉框只列本机已安装的模型，切换立即生效、重启不丢。思考型模型（qwen3 等）与普通模型都能直接换——推理过程由应用层剥离，只显示"思考中"占位，不会污染消息内容。

## 技术栈

| 层 | 选型 |
|---|---|
| 模型服务 | 本机 Ollama（默认 `http://localhost:11434`） |
| 后端 | Python 3.13 + FastAPI + SQLite（WAL 模式） |
| 依赖管理 | uv |
| 前端 | Vue 3（CDN 引入，无构建流程）+ 原生 CSS |
| 流式输出 | SSE（`fetch` + `ReadableStream` 手动解析） |

设计取舍与实现细节见 [DEVELOPMENT.md](./DEVELOPMENT.md)。

## 开始使用

### 1. 准备 Ollama

安装 [Ollama](https://ollama.com/download) 并拉取一个模型：

```powershell
ollama pull qwen2.5:3b
```

确认服务在跑（Ollama 安装后会自动常驻）：

```powershell
curl http://localhost:11434/api/tags
```

小模型响应快、占用低，适合先跑通；想要更好的角色扮演与格式遵循效果，可以换更大的模型（例如 `qwen3.5:4b`），在界面顶栏切换即可。

### 2. 安装 uv

```powershell
powershell -c "irm https://astral.sh/uv/install.ps1 | iex"
```

### 3. 安装依赖

在项目目录下执行（uv 会按 `.python-version` 自动准备 Python 3.13，无需手动装）：

```powershell
uv sync
```

### 4. 启动

```powershell
uv run run.py
```

看到 `Uvicorn running on http://127.0.0.1:17800` 后，浏览器打开：

```
http://127.0.0.1:17800
```

也可以直接双击项目根目录的 `start.bat`：省去开终端敲命令，启动后会自动用默认浏览器打开页面；服务已在运行时再双击一次不会重复启动，只会把页面重新打开。关掉那个命令行窗口即停止服务。

### 5. 第一次使用

1. 在**角色对话**或**角色情境**模式下点"新建角色"，填写角色卡
2. 点"新建会话"（标题可留空，之后会自动命名），开始对话
3. 右侧面板里可以调生成要求、改角色卡、看记忆
4. 想写自由剧本就切到**自由情境**模式，直接新建会话即可

> 两个角色模式的会话是分开的：在角色对话里建的会话不会出现在角色情境的列表里，反之亦然。切模式 Tab 会回到你上次在该模式看的那条会话。

## 界面说明

三栏布局，左右两栏都可以收起，对话内容始终居中：

```
┌──────────┬─────────────────────────────┬──────────────┐
│ 模式Tab  │ [☰] 标题 [模式] [模型] [面板] │              │
│──────────├─────────────────────────────┤  右侧面板     │
│ 列表区    │      消息流（居中留白）       │  · 生成要求   │
│ ·角色列表 │                             │  · 角色卡编辑 │
│ ·或会话   │                             │  · 记忆查看   │
│──────────├─────────────────────────────┤              │
│ [新建]    │  [输入框           ] [发送]  │              │
└──────────┴─────────────────────────────┴──────────────┘
```

- 消息悬停后出现操作条：复制 / 编辑 / 删除 / 重新生成；也可以直接双击气泡进入编辑
- 两种角色模式下，助手消息左侧是**方形头像**（没上传图片就显示姓名首字），**角色名显示在气泡正上方**（微信式）；头像位置固定，换图不影响气泡排版
- 头像在**角色编辑弹窗**和**右侧面板的角色卡**里都能换，也可以一键移除；方形头像同样用在左侧角色列表里
- 选头像后会弹出**裁剪框**（带蓝色边线，白底图片也看得清裁到哪里）：拖动图片调整位置、用滑杆缩放（1×～3×），方框内的部分即头像；点框外或按 Esc 取消。图片不合适（不是图片、超过 10MB、最短边不足 256px、分辨率过高）会在选图处**直接提示原因**，不会静默失败
- 角色有背景图时，对话区显示**背景图**（整图居中、留白），底部中央出现 `‹ 2 / 5 ›` 切换；只有一张时不显示切换键
- 头像与对话背景在**角色编辑弹窗**和**右侧面板的角色卡**里都能管理（面板里背景区就在头像下方）：背景最多 5 张、可一次选多张、可逐张删除
- 背景的**顺序可以调**：直接拖动缩略图，或用缩略图底部的 `‹`/`›` 逐格前移后移。**第一张是打开会话时默认显示的那张**，顺序也决定对话里"上一张/下一张"的先后
- 右侧面板的三个分区（生成要求 / 角色卡 / 记忆）**标题可点，点一下折叠、再点展开**，用法和左侧角色列表的箭头一致；自由情境模式下没有角色卡，所以是两个分区
- **用户消息与生成消息都能重新生成**：用户消息重新生成会保留这条消息本身、只重做它之后的回复；主动"停止"导致没有回复时，这是唯一的补救入口
- 点"编辑"或双击气泡会弹出**居中的编辑框**，长消息也不会把气泡拉变形；点框外或按 Esc 取消
- 删除按钮下方的小菜单，点其他任意位置即自动收起（按 Esc 同样关闭）
- 会话绑定的角色被删除后，该会话只可查看，"重新生成"按钮不再出现
- 右侧面板里改过但还没保存时，该分区的标题旁会出现"未保存"和一个**还原**键：连着点两次即回到上次保存的内容（第一次点只是确认，5 秒内不点第二次会自动取消），不用弹窗确认；面板收起时改由顶栏"面板"按钮上的小圆点提示
- 生成中输入框右侧的按钮变为"停止"
- **自由情境**下发送键上方还有一个"继续"键（还没有可续的回复、或正在生成时置灰），点它等于自动发一条"继续"
- 右侧面板里带"✕"的栏位，那个 ✕ 不参与 Tab 键顺序，但照旧可以鼠标点击清空
- 左侧 `☰` 收起左栏，顶栏"面板"按钮收起右栏，收起后对话区自动重新居中
- 被压缩归档的消息默认折叠为"已归档 N 条"，点击可展开查看原文
- 切换模式 Tab 只换左侧列表与当前会话：两个角色模式的会话互不显示，各自记住上次打开的那条

## 配置

改 `config.yaml` 后重启生效：

```yaml
ollama:
  base_url: http://localhost:11434
  model: qwen2.5:3b              # 首次启动的默认模型；之后以界面选择为准
  options:
    temperature: 0.8
    num_ctx: 8192

memory:
  model: ""                       # 压缩用模型，留空 = 同对话模型
  compress_threshold_chars: 6000  # 未归档消息超过该字符数触发压缩
  archive_batch_size: 20          # 每次归档的消息条数
  max_memory_chars: 600           # 记忆摘要长度上限

chat:
  history_max_messages: 60        # 注入历史的最大条数（从最早开始截断）

naming:
  model: ""                       # 会话自动命名用模型，留空 = 同对话模型
  max_chars: 12                   # 自动标题字数上限
  min_user_chars: 8               # 用户累计发言少于该字数时先不命名

server:
  host: 127.0.0.1
  port: 17800                       # 避开其他项目常用的 8000/8080

backup:
  dir: ./backups                    # 备份目录；相对路径按项目根目录解析，可改成别的盘或网盘
  days: 14                          # 保留最近多少个自然日的备份（每次启动都备，一天可能多份）
  on_startup: true                  # 每次启动应用时自动备份一份

data_dir: ./data                  # 数据库目录
```

想快速验证记忆功能，可以把 `compress_threshold_chars` 临时改小（如 500），聊几轮就能看到归档折叠与记忆内容。

## 数据与备份

所有数据都在 `data/chatbot.db` 这一个 SQLite 文件里（含角色、会话、消息、记忆、模型选择，以及自定义头像与对话背景图）。数据库是单用户设计，没有鉴权，服务只监听 `127.0.0.1`，不要对外暴露。

**应用会自动备份**：**每次启动都导出一份**完整快照到 `backups/`，文件名形如 `chatbot-20260101-123456.db`（同一秒内重复启动会在名字后加 `-2`、`-3` 以免互相覆盖）。每份都先校验完整性再保留，**保留最近 14 个自然日**（含今天），更早的自动清理——所以一天里启动几次就会有几份备份，这是正常的。

> ⚠️ **不要在应用运行时手工复制 `chatbot.db`。** 库跑在 WAL 模式下，最近的对话可能还在 `chatbot.db-wal` 里、尚未并回主文件；只拷 `.db` 会得到一个缺少最后几轮、甚至缺表结构的快照——平时看不出问题，真拿它恢复时才发现丢的正是最后那段。自动备份走的是 SQLite 的在线备份接口，不受此影响。

- **想手动再备一份**：把应用重启一次即可（每次启动都会备一份）。
- **想换个地方存**（另一块盘、或网盘同步目录）：改 `config.yaml` 里的 `backup.dir`，相对路径按项目根目录解析，也可以直接写绝对路径。

**恢复步骤**

1. 关掉应用（那个命令行窗口）
2. 从 `backups/` 里挑一份，复制成 `data/chatbot.db`，并删掉旁边的 `data/chatbot.db-wal` 与 `data/chatbot.db-shm`（如果存在）
3. 重新启动应用

**彻底重置**：删掉 `data/chatbot.db`，下次启动会自动重建空库。`backups/` 里的历史备份不受影响，所以即使误删也还能从备份捞回来。

## 常见问题

**顶栏提示"无法连接 Ollama"**
Ollama 没启动或端口不对。执行 `ollama list` 确认能正常返回，必要时手动启动 Ollama。

**顶栏提示"所选模型未安装"**
上一次选的模型被删了，或换机器后模型没同步。在顶栏下拉框里重新选一个已安装的模型即可。

**生成很慢或首字等很久**
取决于本机模型大小与硬件。换更小的模型（如 `qwen2.5:3b`）会明显变快；界面上会先显示"生成中"，思考型模型会先显示"思考中"，都属于正常等待。

**模型不按格式输出情境**
小模型偶发。程序对标记的识别是宽容的——`SCENERY`/`SCENE`、小写、全角括号都认，台词写在标记之前也算话语，所以偶尔的用词偏差不会把内容打乱。真的一个标记都认不出时，整段会当作话语显示，不丢内容。可以在生成要求里把情境篇幅调小、或用更大的模型改善遵循度。

**某条回复只有情境、没有台词**
模型有时只写了场景。程序会照原样保留（情境显示为情境块，不硬塞台词），这条消息的正文就是空的；要补台词，编辑它即可（只有情境时也允许保存）。

**自由情境总是又写情境又写台词**
在右侧面板把"情境/台词配比"调成"只有情境"或"情境为主"即可。这个字段默认是"均衡"，模型拿不到明确要求时容易两边都写一点。

**在角色对话里看不到我在角色情境建的会话**
这是有意的：两个角色模式的会话列表相互隔离。切到角色情境模式就能看到，两边各自记住上次打开的那条会话。角色卡与长期记忆仍然是共用的。

**删了角色，那个会话还能用吗**
只能查看历史：输入框会禁用，"重新生成"按钮也不再出现。即使直接调接口发起生成也会被拒绝，并且已有消息不会被删除。想继续用就重建一个角色、开新会话。

**记忆什么时候更新**
每次生成完成后后台检查，超过阈值才压缩，不阻塞对话。想立刻看到效果就把阈值改小；压缩结果可在右侧面板查看与手动修改。

**删了消息，记忆会跟着变吗**
不会。记忆是"曾经发生过的事"的沉淀，已归档的内容不随消息删改回滚。需要修正就手动编辑面板里的记忆。

**必须联网吗**
运行时不需要，模型和数据都在本地。只有首次加载页面会从 CDN 取 Vue，如果完全离线，把 `index.html` 里的 Vue script 换成本地文件即可。

**换了端口后打不开页面**
服务端口在 `config.yaml` 的 `server.port`，默认 **17800**（刻意避开其他项目常用的 8000/8080）。用旧书签访问 8000 会连不上，改成 `http://127.0.0.1:17800` 即可，`start.bat`不受影响。

**数据库误删了 / 想回到几天前的状态**
去 `backups/` 里挑一份时间合适的备份，按上面"数据与备份"里的恢复步骤换回去即可（每次启动都会自动备一份，保留最近 14 天）。
