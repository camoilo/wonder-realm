# 多模式对话机器人

一个完全在本机运行的对话应用：模型走本地 Ollama，数据存本地 SQLite，不依赖任何云端 API。支持三种对话模式，带角色设定、可随时调整的生成要求、跨会话的长期记忆，以及完整的消息编辑与重生成能力。

## 三种模式

| 模式 | 生成内容 | 绑定角色 | 长期记忆归属 |
|---|---|---|---|
| **聊天模式** | 只有角色说出的话（像发短信，没有动作与旁白） | 是，会话创建时选定 | 按角色，该角色所有会话共享 |
| **沉浸模式** | 角色话语 + 情境说明（你也能写情境：输入区分「情境」「话语」两栏） | 是，与聊天模式共用同一套角色 | 与聊天模式共用同一份角色记忆 |
| **导演模式** | 自由生成的对话与情境 | 否 | 按会话独立保存 |

聊天模式与沉浸模式共享角色设定和长期记忆——在任一模式下聊过的关键信息，切到另一个模式也记得。角色之间、会话之间的记忆互不可见。

但聊天模式与沉浸模式的**会话列表相互隔离**：聊天模式里只列出聊天模式创建的会话，沉浸模式里只列出沉浸模式创建的会话，互相看不到、也打不开；切换模式 Tab 会回到你上次在该模式看的那条会话。三种模式里，只有导演模式的会话与角色无关。

## 主要功能

**角色设定**：头像（可选）、外观、性格、语言风格、背景故事，随时可改，下一次生成即生效。选头像时的流程是：**先校验**（格式、大小上限 10MB、图片最短边至少 256px），**再拖动裁剪成正方形**（可缩放 1×～3×），保存时缩成 256×256 存进数据库——所以头像跟着数据库一起备份、一起恢复。

**让模型生成角色**：新建角色时可以让模型直接写好整个角色设定（只写文字，不管头像和背景），填一句话描述想要的设定即可，留空则由它自由发挥，不满意可以点"换一个"重来。生成有两种模式：

- **开放模式**：生成的姓名、外观、性格、语言风格、背景故事全部直接展示，可以随便改。
- **探索模式**：只公开**姓名与外观**，另外三项**上锁**——它们照常参与生成（角色的性格是真的存在、会体现在对话里），但界面上不显示，接口也不下发，你得在对话中慢慢了解这个角色。想直接看也可以：点"公开角色设定"，确认后**永久解锁**并开放修改（解锁是单向的，不能反悔再锁上）。

生成用的是**当前选中的模型**，并且**跟着顶栏的思考开关走**——开着思考会明显更慢（实测同一提示词常见 60 秒左右，偶发超过 5 分钟），嫌久可以先关掉思考模式再生成。等待上限默认 600 秒，可在 `config.yaml` 的 `character_gen.timeout` 调整；真超时会明确告诉你是超时，而不是一句没头没尾的失败。

**对话背景**：每个角色最多可放 **5 张**图，在聊天模式 / 沉浸模式下作为对话区背景（**整图居中**，比例不合时两侧或上下留白，既不裁切也不拉伸）；对话区底部中央有 `‹ 2 / 5 ›` 可随时切换。导演模式、未选会话、角色已删除时都保持空白背景。背景图存在数据库里，同样跟着备份走。

**生成要求**：挂在会话上而不是角色上，因此同一个角色可以有"简短闲聊"和"详细演绎"两种用法互不干扰。每个模式一套字段，其中**发散程度**是四个标签（严谨 / 稳定 / 标准 / 放飞），调的是模型每次回答的随机程度——**它不是给模型的文字要求，不写进提示词**，界面上也不显示数值。沉浸模式另有**导演指令**，单独成段注入提示词——它只影响情境与剧情走向，不会作为消息进入对话历史，角色也不会"说出"收到了指令。导演模式另有**情境/台词配比**（只有情境 / 情境为主 / 均衡 / 台词为主）：可以整段只写情境、完全不出现台词，也可以让情境远多于台词，不必两者交替出现。

**长期记忆**：会话内消息超过阈值（默认 20000 字符）后，后台自动把较早的消息压缩成一份结构化摘要，不需要用户操作。摘要会注入后续生成的提示词，可在右侧面板查看与手动修改。摘要长度、压缩阈值、批量条数都可配置。

**会话内搜索**：顶栏右侧有搜索框，输入关键词即时把所有命中处**标黄**（当前那一处用更深的橙色），↑/↓ 在命中之间环形跳转并把它滚到视野中间（Enter 下一个、Shift+Enter 上一个，Esc 或输入框后面那个 × 清空）。框的宽窄不随输入变化：计数、清空键与两个跳转键一直都在，没关键词时只是置灰。搜索覆盖当前显示出来的消息（含情境说明），只搜显示中的——归档折叠着的不参与。关键词按字面匹配、大小写不敏感。

**我的设定（你是谁）**：右侧面板里可以设定**你本人**——头像（可选）、名字、身份、外观。填好之后点面板底部的「保存当前配置」生效。旁边还能**存成预设**（含头像）：预设是"另存的一份"，与当前使用的设定互不影响——面板上只显示"当前预设：谁"，面板上三个键依次是「载入预设…」「编辑预设…」「存为预设」：前两个都会打开**左列表 + 右内容**的弹窗（左边每项带头像与身份摘要，右边分别是只读详情、可编辑字段——名字重复也分得清），「载入这条」**立即生效**，「编辑预设…」里改完列表立刻更新、**删除也在这个弹窗里**；「存为预设」把当前面板里这份另存成一条新预设。**身份与外观会写进聊天与沉浸两种模式的提示词**，让角色知道正在跟谁说话；头像与名字会显示在你自己的消息旁（气泡右侧，与角色消息镜像）。三项都可以留空。导演模式不使用这些内容：那里你是写故事的人，不是故事里的角色，所以那个模式下连这个标签都不出现。

**预设可以绑定角色：同一个角色永远用同一份身份、同一个世界。** 在左侧边栏点角色右边的 ✎ 打开编辑弹窗，最下面有两项：「我的身份预设」与「世界预设」——各选一条预设（含「不绑定」），这个角色的所有会话就都用这份身份与这个世界；选「不绑定」就是不用预设（那种情况下提示词里不出现"你是谁"、也不出现世界设定）。**一份预设可以同时给多个角色用**，改绑也不会动到别的角色。两个预设弹窗里都能看到"这条预设绑给了哪些角色"（列表里每项一行，详情里还有一行"绑定角色"；没绑就是"未绑定"）。打开某个角色的会话时，如果当前用的不是它绑定的那份，会自动换成它绑定的那份——所以换角色就换身份与世界、换会话不变；在面板上临时手改过的内容，只要还在同一个角色的会话里就不会被冲掉（面板上还有**没保存的改动**时，自动切换会让路，绝不覆盖你正在编辑的内容）。删除某条预设时，用了它的角色自动回到"不绑定"。锁定（探索模式）的角色也能改这两项：锁的是角色的隐藏设定，"我用哪份身份、哪个世界"是你自己的事。

**附加属性（角色的状态，可选）**：在右侧「角色设定」标签页里可以给角色定义几条**会随剧情变化的属性**——比如好感、心情、表情、健康状况。每条要有**名称**（如"好感"）和**类型**（**文字型**记一句话，如"有点紧张"；**百分比型**记 0–100 的数），还能写一句**解释**告诉模型这个属性是什么意思（可留空）。最多 8 条；名称留空的行保存时自动丢掉，填了名称就必须选类型。

定义好之后，模型**每一轮都会在回复末尾附上这些属性的当前值**（这一段不会出现在对话里，你看不到它），值跟着那条消息一起存进数据库；对话页**顶部会浮出一块可收纳的状态面板**（宽度适中：不是一条小窄条，也不铺满整行）——文字型直接显示文字，百分比型显示成一条横向进度条加数值，显示的是**最近一条带属性的消息**那一份，所以刚发完言它也不会闪空。**收起时它只是一个图标**（点一下展开，展开才列出每条属性的详情）；它贴在对话页顶部：不滚动时它把消息规规矩矩地排在下面，往下翻消息时它停在最上面、消息从它下面滑过。**属性不会出现在消息气泡里**：那是幕后的状态，不是角色说出口的话。想手改就点那条消息的「编辑」，弹窗里会按角色的定义列出这些属性（百分比型是数字框，留空表示"没设置"）。

发给模型时**只用上一条消息的那一份**，不会把历史每轮的属性都塞进去：严格取这一轮输入之前的那条消息；当前会话还没有上一条（比如这是新会话的第一句）就退到**这个角色所有会话里时间最近的那一条**；那个角色还没有任何消息、或那条消息没有属性时不注入（模型会给一个合理的初始值）。**导演模式没有这一套**：那里没有固定的角色，也就没有"角色的状态"。

**世界设定**：右侧面板里可以给故事定一个**世界**——**世界名称**（只给自己辨认，**不发给模型**）、**描述**（详细信息）、**规则**（独属于这个世界的规则）与**词库**（专有名词及其解释，一条一行，可增删）。四项都可以留空，也可以随时改，下一次生成即生效。三种模式都用得上（导演模式的故事同样发生在某个世界里）。除了名称，描述 / 规则 / 词库都会写进提示词，位置在**角色设定之前**——世界是最外层的框架：模型会遵守这些设定、按给定含义使用词库里的名词，但不会把这份设定原文念出来。

**世界也有一套预设，用法和"我的设定"完全一样**：世界标签顶部一行"当前世界预设：X" + 三个键「载入预设…」「编辑预设…」「存为预设」，弹窗里同样是左列表 + 右详情（详情列名称、描述、规则与词库逐条）。**用哪份世界由绑定决定**：聊天与沉浸两种模式跟角色走（就是上面那个「世界预设」下拉）；**导演模式没有角色，所以每个导演会话各自带一份**——新建导演会话时在弹窗里选（默认选你正在用的那条），建好后也能在「世界设定」标签顶部那行「本会话的世界预设」里改，选「不用世界」表示这个会话不注入世界设定。

**每处输入都有字数上限**：消息与情境 2000 字、角色姓名 20 字、外观 / 性格 / 语言风格 600 字、背景故事 1200 字、题材文风 60 字、附加要求与导演指令 500 字、记忆 2000 字、会话标题 40 字、生成提示词 200 字、我的设定里的名字 20 字 / 身份 300 字 / 外观 600 字、世界名称 40 字 / 描述 2000 字 / 规则 2000 字、词库每条的名词 30 字 / 解释 150 字且最多 30 条、附加属性每条的名称 20 字 / 解释 200 字 / 文字值 100 字且最多 8 条。输入框**右下角实时显示"已用 / 上限"**，到九成时转橙色提醒；到上限就打不进更多字（粘贴超长也会被截），直接调接口同样会被拒（422）。上限只写在后端一处（`app/limits.py`），前端从 `/api/limits` 取同一份数字，不会出现"打得进、存不下"。

**消息操作**：任意消息都可编辑（点气泡下方的"编辑"，弹窗居中显示）与删除（单条或连着后面一起删）；生成消息可重新生成，以该消息之前的上下文为基准替换。**用户消息也能重新生成**——保留这条消息、只重做它之后的回复，所以中途"停止"导致这轮没有回复时可以直接重来。生成过程中可以随时**停止**，已经流出的部分照常保留，不会白费。会话绑定的角色被删除后，该会话只可查看，重新生成按钮不再提供（即使通过接口发起也会被拒绝，且不会删掉已有消息）。

**继续生成**：导演模式下，发送键上方有一个"继续"键，点一下等于自动替你发一条"继续"，让模型接着上一条回复往下写——想让它多写一段又懒得打字时很方便。它不会动你输入框里正在写的草稿。

**会话标题自动命名**：创建会话时留空标题，说够内容后由模型异步总结一个标题；手动改过名的会话不会再被自动覆盖。

**模型随时切换**：顶栏下拉框只列本机已安装的模型，切换立即生效、重启不丢。**首次使用不预选模型**——先在顶栏选一个；之后每次启动都沿用你上次的选择。没选模型时顶栏会提示，真去生成也会明确告诉你要先选模型，而不是抛一句看不懂的报错。思考型模型（qwen3 等）与普通模型都能直接换——推理过程由应用层剥离，只显示"思考中"占位，不会污染消息内容。

**思考模式开关**：模型下拉框旁边有一个开关，可以**关掉思考模式**。思考型模型在回答前会先推理一遍，关掉它能明显加快回复（实测同一个模型从 8.4 秒降到 1.4 秒）；普通模型没有思考模式，这个开关会置灰、点了也不起作用。选择会记住，重启仍生效。

## 技术栈

| 层 | 选型 |
|---|---|
| 模型服务 | 本机 Ollama（默认 `http://localhost:11434`） |
| 后端 | Python 3.13 + FastAPI + SQLite（WAL 模式） |
| 依赖管理 | uv |
| 前端 | Vue 3 + Vite 构建（源码在 `frontend/`，产物提交在 `app/static/`）+ 原生 CSS |
| 流式输出 | SSE（`fetch` + `ReadableStream` 手动解析） |
| 电脑端（可选） | Electron 外壳（`desktop/`）：同一个后端 + 同一份网页，另加"配置 / 手机视图"两个键 |

设计取舍与实现细节见 [DEVELOPMENT.md](./DEVELOPMENT.md)。

## 开始使用

### 1. 准备 Ollama

安装 [Ollama](https://ollama.com/download) 并拉取一个模型：

```powershell
ollama pull qwen2.5:3b
```

**不用特意先把它打开**：启动应用时会自动检测，没在运行就顺手帮你启动（`ollama serve`，不会跟着应用一起退出，你在别处接着用也没问题）。只有根本没装 Ollama 时才会提示你去装——那种情况下应用照样能打开，只是不能生成。

确认服务在跑（Ollama 安装后会自动常驻）：

```powershell
curl http://localhost:11434/api/tags
```

小模型响应快、占用低，适合先跑通；想要更好的角色扮演与格式遵循效果，可以换更大的模型（例如 `qwen3.5:4b`），在界面顶栏切换即可。

**（可选）把 KV cache 量化打开，给长上下文省一半内存**：本项目把上下文窗口默认设成 32768 token，而 Ollama 的 KV cache 默认是 f16，在这个窗口下要占约 1 GB。设一个用户环境变量就能量化成 q8_0（质量基本无损）：

```powershell
[Environment]::SetEnvironmentVariable("OLLAMA_KV_CACHE_TYPE", "q8_0", "User")
```

然后**从托盘退出 Ollama，再从开始菜单重新启动**（这个变量由托盘应用传给服务进程，不重启不生效）。实测 `qwen3.5:4b` 在 32768 窗口下总占用从 4085 MiB 降到 3606 MiB（KV cache 从 1024 MiB 降到 544 MiB）。它是 Ollama 服务端的**全局**设置，会影响这台机器上所有连 Ollama 的程序；不设也完全能跑，只是多用几百 MB 内存。

### 2. 安装 uv

```powershell
powershell -c "irm https://astral.sh/uv/install.ps1 | iex"
```

### 3. 安装依赖

在项目目录下执行（uv 会按 `.python-version` 自动准备 Python 3.13，无需手动装）：

```powershell
uv sync
```

### 4. 启动

```powershell
uv run run.py
```

看到 `Uvicorn running on http://127.0.0.1:17800` 后，浏览器打开：

```
http://127.0.0.1:17800
```

也可以直接双击项目根目录的 `start.bat`：省去开终端敲命令，启动后会自动用默认浏览器打开页面；服务已在运行时再双击一次不会重复启动，只会把页面重新打开。关掉那个命令行窗口即停止服务。

### 5. 改前端（一般用不到）

前端是 **Vue 3 + Vite** 构建的，**构建产物已经提交在 `app/static/`**，所以只是"用"这个应用的话不需要装 Node（`start.bat` 与 `start_desktop.bat` 检测到 Node 时会顺手重建一次，其余情况直接用已提交的产物）。

要改前端（源码在 `frontend/`）时：

```powershell
cd frontend
npm install            # 只需一次
npm run build          # 产物写进 ../app/static，然后刷新页面即可
```

调界面时更推荐开发模式（改完立刻热更新，不用反复构建、也不用重启后端）：

```powershell
# 一个终端跑后端
uv run run.py
# 另一个终端跑前端
cd frontend
npm run dev            # http://127.0.0.1:5173，/api 自动代理到 17800
```

### 6. 第一次使用

1. 在**聊天模式**或**沉浸模式**模式下点"新建角色"，填写角色设定；也可以让模型**自动生成**一个（见下）
2. 点"新建会话"（标题可留空，之后会自动命名），开始对话
3. 右侧面板里可以调生成要求、改角色设定、看记忆
4. 想写自由剧本就切到**导演模式**模式，直接新建会话即可

> 聊天模式与沉浸模式的会话是分开的：在聊天模式里建的会话不会出现在沉浸模式的列表里，反之亦然。切模式 Tab 会回到你上次在该模式看的那条会话。

## 界面说明

三栏布局，左右两栏都可以收起，对话内容始终居中（**手机上是单栏**，见下文「手机 / 局域网访问」）：

```
┌──────────┬─────────────────────────────────────────────────────┐
│模式Tab   │ [☰] 标题 [模式]     [搜索] [模型] [思考] [配置]     │
│(三模式)  ├──────────────────────────────────────┬──────────────┤
│──────────│                                      │  右侧面板    │
│列表区    │          消息流（居中留白）          │  · 生成要求  │
│·角色列表 │                                      │  · 世界设定  │
│·或会话   │                                      │  · 角色设定  │
│──────────├──────────────────────────────────────┤  · 记忆查看  │
│[新建]    │      [输入框        ] [发送][↓]      │              │
└──────────┴──────────────────────────────────────┴──────────────┘
```

- 每条消息的**气泡上方那一行显示名字与发送时间**（精确到秒，如 `12:34:45`）：聊天与沉浸两种模式下是"角色名 + 时间"（你自己的消息显示你在"我的设定"里填的名字，靠右）；导演模式没有名字，那一行就只有时间。鼠标悬停在时间上可以看到完整日期时间
- 消息悬停后出现操作条：复制 / 编辑 / 删除 / 重新生成（这几个键自带文字，所以没有额外的悬停提示）
- 聊天模式与沉浸模式下，助手消息左侧是**方形头像**（没上传图片就显示姓名首字），**角色名显示在气泡正上方**（微信式）；头像位置固定，换图不影响气泡排版
- 头像在**角色编辑弹窗**和**右侧面板的角色设定**里都能换，也可以一键移除；方形头像同样用在左侧角色列表里
- 选头像后会弹出**裁剪框**（带蓝色边线，白底图片也看得清裁到哪里）：拖动图片调整位置、用滑杆缩放（1×～3×），方框内的部分即头像；点框外或按 Esc 取消。图片不合适（不是图片、超过 10MB、最短边不足 256px、分辨率过高）会在选图处**直接提示原因**，不会静默失败
- 角色有背景图时，对话区显示**背景图**（整图居中、留白），底部中央出现 `‹ 2 / 5 ›` 切换键；**旁边还有一个「关闭背景」键**，点一下暂时不显示背景（按钮变成「显示背景」，切会话或刷新后恢复显示）。只有一张图时翻页键置灰，但关闭键照旧可用
- 头像与对话背景在**角色编辑弹窗**和**右侧面板的角色设定**里都能管理（面板里背景区就在头像下方）：背景最多 5 张、可一次选多张、可逐张删除
- 背景的**顺序可以调**：直接拖动缩略图，或用缩略图底部的 `‹`/`›` 逐格前移后移。**第一张是打开会话时默认显示的那张**，顺序也决定对话里"上一张/下一张"的先后
- 右侧面板是**标签页**：生成要求 / 世界设定 / 角色设定 / 我的设定 / 记忆（导演模式只有生成要求、世界设定与记忆）。**世界设定与我的设定各自都有一行"当前…预设"和三个预设键**，预设的挑选 / 查看 / 编辑 / 删除都在弹窗里。每个标签**都有边框**（选中的那个用蓝色边框 + 白底标出），标签区与下面内容之间有一条明显的分隔线——左侧栏（"模式选择"下方、模式按钮下方）用的是同一款线。**标签栏固定在面板顶部、保存键固定在面板底部**（统一写「保存当前配置」），内容再长也不会被滚轮带走，也不会被内容量挤走；哪个标签有没保存的改动，它的右上角会出现一个小圆点，底部同时出现「未保存 / 还原」那一行（还原键还是"点两次确认"）。五个标签在 330px 面板里排成两行（3+2），不会把"生成要求"截成"生成要…"
- **"配置"开关常驻在窗口右上角，位置永远不变**：打开或收起面板它都待在同一格（只有箭头方向变），没有会话时也在原位、只是变灰点不动——所以可以"不用挪鼠标点开、看一眼、再点关"。面板里没有第二个开关，不会出现两个入口状态打架（顶栏因此横跨对话区与面板，面板展开时搜索 / 模型 / 思考这三个控件会位于面板上方）
- **删除角色只在左侧边栏**：点角色旁的 ✎ 打开编辑弹窗，里面的「删除角色」是唯一入口；右侧面板不再放删除键，避免在改设定的地方误删角色
- **用户消息与生成消息都能重新生成**：用户消息重新生成会保留这条消息本身、只重做它之后的回复；主动"停止"导致没有回复时，这是唯一的补救入口
- 点"编辑"会弹出**居中的编辑框**，长消息也不会把气泡拉变形；点框外或按 Esc 取消。聊天与沉浸模式下，编辑框里还会按角色的定义列出**附加属性**（见上文），改完与正文一起保存
- 新建/编辑角色的弹窗与编辑消息的弹窗**同宽（780px）**，五个设定框都有足够高度——角色设定是要写几段话的，不该在一个两三行的小框里来回滚。**新建会话**的弹窗按模式给字段：聊天与沉浸模式下选角色 + 可选标题；导演模式下选这个会话的世界预设 + 可选标题
- 这两个弹窗底部的**取消 / 保存钉在弹窗底部**（连同"删除角色"和保存失败的提示）：内容再长、滚到哪一段，它们都在原处不动，不用先滚到底才能按
- 删除按钮下方的小菜单，点其他任意位置即自动收起（按 Esc 同样关闭）
- 会话绑定的角色被删除后，该会话只可查看，"重新生成"按钮不再出现
- 右侧面板里改过但还没保存时，该标签的右上角会出现一个小圆点，底部出现"未保存"和一个**还原**键：连着点两次即回到上次保存的内容（第一次点只是确认，5 秒内不点第二次会自动取消），不用弹窗确认；面板收起时小圆点仍挂在最右那条常驻的图标列上
- 生成中输入框右侧的按钮变为"停止"
- **沉浸模式的输入区是两栏**：「情境说明」（场景 / 动作 / 心理，**可选**，占左边较窄一栏）与「话语」（**必填**）。两栏都会发给模型——你写的场景模型看得到；只填情境、不写话语时发送键是灰的。Enter 发送、Shift+Enter 换行，两栏都适用；聊天模式与导演模式仍是一个输入框
- 发送键右侧还有个 **↓ 键**：往上翻看历史之后，点它直接平滑滚回最新一条，不用一路拖滚动条
- 定义了**附加属性**时，对话页顶部会浮出一块**可收纳的状态面板**——文字型直接显示文字、百分比型显示成横向进度条加数值。**收起时它只是一个图标**（点一下展开），展开才列出每条属性的详情；它贴在对话页顶部，往下翻消息时会一直停在最上面，消息从它下面滑过（见上文）
- **导演模式**下发送键上方还有一个"继续"键（还没有可续的回复、或正在生成时置灰），点它等于自动发一条"继续"
- 右侧面板里带"×"的栏位，那个 × 不参与 Tab 键顺序，但照旧可以鼠标点击清空
- 每个输入框右下角都有 `已用/上限` 的实时计数（单行框里垂直居中、多行框里贴右下角），到九成变橙色
- **探索模式生成的角色**：右侧面板和"编辑角色"弹窗里，性格 / 语言风格 / 背景故事显示为一块 `🔒 已锁定` 说明，点其中的"公开角色设定"并确认后永久解锁；锁定期这两个入口只显示姓名与外观
- 左侧栏顶部有 **模式选择** 标题（居中加粗，下方一条分隔线）和三个模式按钮（聊天模式 / 沉浸模式 / 导演模式），点一下切换模式；**鼠标移上去（或键盘 Tab 聚焦）会浮出一句这个模式是干什么的**，不挡任何控件
- 界面上带说明的按钮、图标都会在**悬停或键盘聚焦时弹出一张深色小卡片**（模式介绍、搜索框、思考开关、↓/↑ 键、消息操作、面板还原键…都是同一套样式）：贴在元素下方，空间不够自动翻到上方，靠近窗口边缘会自己收进来，移开即消失
- 顶栏**模型下拉框左边**是**会话内搜索框**：输入即标黄，↑/↓ 或 Enter/Shift+Enter 在命中之间跳，**Esc 清空**；计数与两个跳转键一直都在（不随输入出现消失，所以框的宽窄始终不变）
- 左侧 `☰` 收起左栏；右栏点最右那条图标列上**当前高亮**的图标收起（图标列常驻、不随面板开合移动），收起后对话区自动重新居中
- 被压缩归档的消息默认折叠为"已归档 N 条"，点击可展开查看原文
- 切换模式 Tab 只换左侧列表与当前会话：聊天模式与沉浸模式的会话互不显示，各自记住上次打开的那条

## 电脑端（Electron 外壳）

除了"开浏览器用"，也可以把它当**电脑端应用**用：界面与网页版**完全一样**，只多两个键：右下图标列最低栏一个 **⚙ 配置**、顶栏主题键旁一个 **📱 手机视图**。

```bat
npm install --prefix desktop      :: 只需一次（下载 Electron 运行时，约 110MB）
start_desktop.bat                 :: 以后双击这个就行
```

双击 `start_desktop.bat` 时会像 `start.bat` 那样**顺手重建一次前端**（判断逻辑完全一致：装了 Node 且 `frontend/node_modules` 在才做），所以改完前端直接双击它就能看到效果。

下载慢的话加个国内镜像：`set ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/` 再执行上面那条 `npm install`。装完建议确认一下 `desktop\node_modules\electron\dist\electron.exe --version` 能打印版本号（能打印才算装全）；zip 会缓存在 `%LOCALAPPDATA%\electron\Cache`，所以之后补装/重装通常只要几秒。

多出来的两个键：

- **⚙ 配置**（右侧图标列**最低栏**，那个总是高亮的小齿轮）：打开一个小面板，从上到下是——
  - 「推送局域网」开关（开/关**立即生效**，不用重启）。**默认是关的**，要在手机上用就先打开；
  - 一行状态：端口 / Ollama 是否连上（含模型个数）/ 局域网开关；
  - **二维码**：手机扫一下就能打开（局域网关着时二维码会置灰，并提示先打开开关）；下面同时给出地址和一个「复制」键；
  - 「手机视图」一键收纳成手机大小；
  - **复制防火墙命令**：把放行入站 17800 的那条 `netsh` 命令放进剪贴板，粘到**管理员** PowerShell 里执行一次即可（README 下面那条命令是同一份）；
  - **打开日志文件**：用记事本打开壳日志，出问题时不用自己去翻 `%APPDATA%`。
  > 没打开任何会话时，右侧图标列整块不存在——那时这个 ⚙ 会出现在顶栏，免得你进不去配置。
- **📱 手机视图**（顶栏主题键旁，也可以按 `F9` 或菜单「视图 → 手机视图」）：点一下把窗口**收成手机大小**，界面立刻变成手机上那套单栏布局（左栏抽屉、右面板底部弹出、辅助键收进「⋯」）。**宽度锁在 390**（保证就是手机单栏那个样子），**高度可以自己拖**，窗口会记住你上次拖的高度；这时两个桌面键会隐藏，再点一次（或 F9）恢复原来的桌面大小。想预览手机上的效果、或就在电脑上小窗用，都很方便。

手机上的用法与网页版完全一致：手机连同一个 WiFi，打开「配置」里那个地址即可（后端、数据、界面都是同一份）。详细的连不上排查见下面「手机 / 局域网访问」。

> 现在这版外壳复用项目里的 Python 环境；**打包成"别人机器上免装 Python"的安装包**（PyInstaller + electron-builder）是下一步的计划，见 DEVELOPMENT §10.9。

## 手机 / 局域网访问

**手机上也能用**：窄屏下界面自动变成单栏——左栏收成**抽屉**（点左上 `☰` 滑出）、右侧面板改成**从底部弹出**（点顶栏的四宫格图标）、底部那些辅助键（背景切换 / 继续 / 跳底 / 情境）统一收进 **「⋯」**，悬停提示改成点击显示。功能一样是全的（三种模式、角色/世界/我的设定、记忆、生成要求都在）。

手机连电脑上这份应用：

1. 电脑与手机连**同一个 WiFi**；
2. **打开"推送局域网"**：电脑端（Electron）点右侧图标列最低栏的 ⚙ 配置 → 打开开关（没打开会话时这个键在顶栏）；如果用的是网页版/命令行，执行 `uv run run.py --lan`（或启动后 `curl` 调一次 `PUT /api/settings`）。**默认是关的**，这是安全默认值；
3. 手机浏览器**扫一下配置面板里的二维码**（或手输 `http://<电脑IP>:17800`）——看到的是**同一份数据**（会话、角色、设定全都在这台电脑上，手机只是浏览器）；面板里也给出这个地址，可一键复制；
4. 打不开多半是防火墙：用**管理员** PowerShell 放行入站 17800（一次就够）：
   `netsh advfirewall firewall add rule name="OllamaAgent 局域网访问 17800" dir=in action=allow protocol=TCP localport=17800`

**不想让局域网访问**：把「推送局域网」开关关掉（立即生效，不用重启、也不用删防火墙规则）；想连端口都不对外，再把 `server.host` 改回 `127.0.0.1` 并重启，最后可删掉上面那条规则（`… delete rule name="OllamaAgent 局域网访问 17800"`）。手机自适应布局与这个开关**互不影响**。

**安全提醒**：应用**没有账号体系**，同一网络里能访问这个端口的人都能读写你的会话。只在可信的家庭/办公网络开放，公共 WiFi 请改回 `127.0.0.1`。

> 后续计划把它做成**电脑端应用**（Electron）：双击即用，打开后手机照样能连局域网访问同一份网页端。

## 配置

改 `config.yaml` 后重启生效：

```yaml
ollama:
  base_url: http://localhost:11434
  model: ""                     # 首次使用不预选模型（留空），由用户在顶栏选；
                                 # 之后每次启动沿用上次的选择（存在库里的 app_settings）
  options:
    temperature: 0.9               # 兜底值：对话实际用会话的“发散程度”档位（标准档 = 0.9），
                                   # 记忆压缩与自动命名各自压到 0.3，改这里不影响它们
    num_ctx: 32768                 # 上下文窗口（token）。Ollama 默认 4096，这里显式加大；
                                   # 超窗时 Ollama 会从最前面静默截断，要和下面的记忆阈值配套改

memory:
  model: ""                       # 压缩用模型，留空 = 同对话模型
  compress_threshold_chars: 20000 # 未归档消息超过该字符数触发压缩（中文约 1.33 字/token）
  archive_batch_size: 20          # 每次归档的消息条数
  max_memory_chars: 600           # 记忆摘要长度上限

character_gen:
  timeout: 600                    # 让模型生成角色的等待上限（秒）。思考型模型开着思考很慢
                                  # （实测常见 60 秒、偶发超过 300 秒），嫌久可先关掉思考模式

chat:
  history_max_messages: 60        # 注入历史的最大条数（从最早开始截断）

naming:
  model: ""                       # 会话自动命名用模型，留空 = 同对话模型
  max_chars: 12                   # 自动标题字数上限
  min_user_chars: 8               # 用户累计发言少于该字数时先不命名

server:
  host: 127.0.0.1
  port: 17800                       # 避开其他项目常用的 8000/8080

backup:
  dir: ./backups                    # 备份目录；相对路径按项目根目录解析，可改成别的盘或网盘
  days: 14                          # 保留最近多少个自然日的备份（每次启动都备，一天可能多份）
  on_startup: true                  # 每次启动应用时自动备份一份

data_dir: ./data                  # 数据库目录
```

想快速验证记忆功能，可以把 `compress_threshold_chars` 临时改小（如 500），聊几轮就能看到归档折叠与记忆内容。

## 数据与备份

所有数据都在 `data/chatbot.db` 这一个 SQLite 文件里（含角色、会话、消息、记忆、模型选择，以及自定义头像与对话背景图）。数据库是单用户设计，没有鉴权，服务只监听 `127.0.0.1`，不要对外暴露。

**应用会自动备份**：**每次启动都导出一份**完整快照到 `backups/`，文件名形如 `chatbot-20260101-123456.db`（同一秒内重复启动会在名字后加 `-2`、`-3` 以免互相覆盖）。每份都先校验完整性再保留，**保留最近 14 个自然日**（含今天），更早的自动清理——所以一天里启动几次就会有几份备份，这是正常的。

> ⚠️ **不要在应用运行时手工复制 `chatbot.db`。** 库跑在 WAL 模式下，最近的对话可能还在 `chatbot.db-wal` 里、尚未并回主文件；只拷 `.db` 会得到一个缺少最后几轮、甚至缺表结构的快照——平时看不出问题，真拿它恢复时才发现丢的正是最后那段。自动备份走的是 SQLite 的在线备份接口，不受此影响。

- **想手动再备一份**：把应用重启一次即可（每次启动都会备一份）。
- **想换个地方存**（另一块盘、或网盘同步目录）：改 `config.yaml` 里的 `backup.dir`，相对路径按项目根目录解析，也可以直接写绝对路径。

**恢复步骤**

1. 关掉应用（那个命令行窗口）
2. 从 `backups/` 里挑一份，复制成 `data/chatbot.db`，并删掉旁边的 `data/chatbot.db-wal` 与 `data/chatbot.db-shm`（如果存在）
3. 重新启动应用

**彻底重置**：删掉 `data/chatbot.db`，下次启动会自动重建空库；**应用正在运行时删掉整个 `data/` 目录也不用重启**——下一个请求会把空库建回来（见 DEVELOPMENT.md 第 9 章「开发约定与强调」）。`backups/` 里的历史备份不受影响，所以即使误删也还能从备份捞回来。

## 常见问题

**顶栏提示"无法连接 Ollama"**
Ollama 没启动或端口不对。启动应用时会自动尝试拉起它（见「开始使用」第 1 步），所以先等几秒再点一下重试；仍不行就执行 `ollama list` 确认命令行能用，必要时手动 `ollama serve`。

**顶栏提示"所选模型未安装"**
上一次选的模型被删了，或换机器后模型没同步。在顶栏下拉框里重新选一个已安装的模型即可。

**生成很慢或首字等很久**
取决于本机模型大小与硬件。换更小的模型（如 `qwen2.5:3b`）会明显变快；界面上会先显示"生成中"，思考型模型会先显示"思考中"，都属于正常等待。

**模型不按格式输出情境**
小模型偶发。程序对标记的识别是宽容的——`SCENERY`/`SCENE`、小写、全角括号都认，台词写在标记之前也算话语，所以偶尔的用词偏差不会把内容打乱。真的一个标记都认不出时，整段会当作话语显示，不丢内容。可以在生成要求里把情境篇幅调小、或用更大的模型改善遵循度。

**某条回复只有情境、没有台词**
模型有时只写了场景。程序会照原样保留（情境显示为情境块，不硬塞台词），这条消息的正文就是空的；要补台词，编辑它即可（只有情境时也允许保存）。

**导演模式总是又写情境又写台词**
在右侧面板把"情境/台词配比"调成"只有情境"或"情境为主"即可。这个字段默认是"均衡"，模型拿不到明确要求时容易两边都写一点。

**在聊天模式里看不到我在沉浸模式建的会话**
这是有意的：聊天模式与沉浸模式的会话列表相互隔离。切到沉浸模式就能看到，两边各自记住上次打开的那条会话。角色设定与长期记忆仍然是共用的。

**删了角色，那个会话还能用吗**
只能查看历史：输入框会禁用，"重新生成"按钮也不再出现。即使直接调接口发起生成也会被拒绝，并且已有消息不会被删除。想继续用就重建一个角色、开新会话。

**记忆什么时候更新**
每次生成完成后后台检查，超过阈值才压缩，不阻塞对话。想立刻看到效果就把阈值改小；压缩结果可在右侧面板查看与手动修改。

**删了消息，记忆会跟着变吗**
不会。记忆是"曾经发生过的事"的沉淀，已归档的内容不随消息删改回滚。需要修正就手动编辑面板里的记忆。

**必须联网吗**
不需要。模型、数据、前端资源全在本机：前端由 Vite 打包（Vue 与生成二维码的那个库也在包里），页面不再从 CDN 取任何东西，断网也能正常使用。只有重新构建前端时才需要联网装 npm 依赖（`frontend/node_modules` 装好后也不必再联网）。

**换了端口后打不开页面**
服务端口在 `config.yaml` 的 `server.port`，默认 **17800**（刻意避开其他项目常用的 8000/8080）。用旧书签访问 8000 会连不上，改成 `http://127.0.0.1:17800` 即可，`start.bat`不受影响。

**手机连不上（打不开 `http://192.168.x.x:17800`）**
依次查：① 手机与电脑在同一个 WiFi（公司/学校网络常禁止设备互访，换手机热点试）；② **「推送局域网」开关是不是开着**（电脑端 ⚙ 配置，在右侧图标列最低栏；命令行用户用 `run.py --lan`）——它默认关，这是最常见的原因；③ Windows 防火墙放行了入站 TCP 17800（管理员 PowerShell 执行上文那条 `netsh` 命令，配置面板里有「复制防火墙命令」键）；④ 地址抄错了——配置面板给出的那个地址最准，直接**扫码**也行（也可以自己在电脑上 `ipconfig` 取 IPv4）。

**双击 `start_desktop.bat` 提示要装依赖（可明明装过）**
它检查的是 `desktop\node_modules\electron\dist\electron.exe` 这个**文件**，不是 `node_modules` 目录。electron 装完还要另外下约 110MB 的运行时，国内直连 GitHub 常卡住或被打断，于是出现"目录在、本体没下来"这种半装状态——按提示里那两条命令重装一次即可（先设镜像）。`npm install` 输出里的 `allow-scripts` 警告可以忽略，脚本仍会执行。

**数据库误删了 / 想回到几天前的状态**
去 `backups/` 里挑一份时间合适的备份，按上面"数据与备份"里的恢复步骤换回去即可（每次启动都会自动备一份，保留最近 14 天）。
